# ZK-011 Scoring and Forbid Rules Implementation Plan

**Date:** 2026-09-13  
**Status:** In execution. Approved by user.

## Scope

Implement evidence-supported edit counting, budget and forbid rules enforcement, score computation, and concept weakness updates in `zedkata-core` under `crates/zedkata-core/src/scoring.rs` and integrate with `crates/zedkata-core/src/verification.rs`.

## Tasks

1. **ZK-011.1: Count evidence-supported edit units**
   - Implement `count_edit_units(edits: &[RecordedEdit]) -> u32` in `crates/zedkata-core/src/scoring.rs`.
   - Distinguish operator deletions (e.g., `dw` removing a word span in 1 edit unit) from discrete single-character deletions (e.g., backspaces counting 1 unit each).
   - Coalesce contiguous single-character typing bursts in insert mode into single edit units (`par_edits = 1` for `ci"` + typing replacement text).
   - Detect undo/inverse edits where an immediate edit reverses the preceding edit and adjust/exclude edit counts accordingly.
   - Validate against retained Phase 0 matrix fixtures (`01-dw.jsonl`, `02-dw-repeat.jsonl`, `03-backspace.jsonl`).

2. **ZK-011.2: Enforce budgets and supported forbid rules**
   - Implement `check_forbid_rules(edits: &[RecordedEdit], rules: Option<&ForbidRules>) -> Result<(), String>`.
   - Enforce `backspace_run`: fail with actionable reason if consecutive single-character deletions reach or exceed the limit.
   - Validate unobservable forbid rules rejection during lesson parsing.
   - Wire forbid rule checks and edit budget validation into `verify_attempt` in `verification.rs`.

3. **ZK-011.3: Calculate score and weakness updates**
   - Implement `calculate_score(actual_edits: u32, par_edits: Option<u32>, max_edits: Option<u32>) -> (bool, u32)` supporting both budgeted and goal-only exercises.
   - Implement `update_weaknesses(current: &HashMap<String, f64>, concepts: &[String], passed: bool, score: u32) -> HashMap<String, f64>`.
   - Implement `create_history_entry(...) -> HistoryEntry`.
